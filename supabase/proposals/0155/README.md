# Proposal 0155 -- finding F-01 (unsafe 0137 carrier inference) -- NOT APPROVED FOR PRODUCTION, NOT APPLIED

0137 (historical, unmodified) assigned `factoring_relationships.carrier_id` when an organization has ONE carrier of any status (R1) or when the factored invoices that CAN be resolved point to one carrier even if others resolve to none (R2). `proposed_0155.sql` adds a strict, read-only evidence layer and a reviewed correction workflow:
* **Evidence hierarchy** (only these; no recency, majority, first/newest row): invoice level = the invoice's dispatch and load carriers, valid only if active and in the invoice's organization, with no structural contradiction; relationship level L1 = every factored invoice proves the same one carrier, L2 = the organization's sole carrier is active and nothing contradicts it; otherwise unresolved (partial / conflict / invalid_carrier / no_evidence).
* **The migration assigns and clears nothing.** It records a review row per unsupported relationship (with the evidence), opens exception records through the 0154 owner-only writer, and writes a run row with counts and digests (candidate, supported, assignable, ambiguous, unsafe, refused, decided, resolved=0). Re-running is idempotent.
* **Owner/admin decision RPC** `decide_carrier_inference_review`: `assign_proven` (re-verifies the strict evidence), `assign_owner` (explicit active same-organization carrier + evidence reference; refused if evidence names other carriers), `confirm`, `retire` (a wrong assignment is never cleared or repointed; deactivate + new relationship per 0138). A non-null carrier is never overwritten; decisions are idempotent (key + fingerprint) and audited.
* Invoices and payments are never assigned a carrier (no such column exists) and are never evidence of one.
Owner questions: OWNER_DECISIONS in `../0156/OWNER_DECISIONS.md` (D-08i) and the worksheet rows C01-C04. Tests: `../0154/tests.py`.
