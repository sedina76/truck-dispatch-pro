## Issuance and reissue workflow (the application gap of F-08, closed LOCALLY only)
1. **Preview** -- `preview_carrier_invoice_issuance(carrier, load_ids, recipient_type, recipient_id)` (read-only). The server resolves: the carrier and its billing mode (direct / factored / unconfigured), for a factored carrier the single active default relationship, factor, NOA, routing, advance/fee/reserve and expected amounts, the recipient, the loads and amounts (`load_financials`), and the SEPARATE dispatch fee estimate. It refuses: mixed carriers / organizations / brokers, undelivered or unpriced loads, loads already on a live invoice, unconfigured or inactive carriers, a missing invoice code, zero or multiple active defaults, an inactive factor, an unready classifier, and unresolved 0155 reviews / open legacy exceptions.
2. **Draft** -- `create_carrier_invoice_draft_from_loads(..., key)`: atomic, idempotent (unique `(organization, key)` + request fingerprint), per-load advisory locks in ascending order, then re-evaluation under the locks. Writes the invoice (`draft`), load links, freight lines, and one **billable-ledger** row per load (partial unique index: a load is live on at most ONE invoice).
3. **Ready** -- `mark_carrier_invoice_ready_for_issue(id, expected_updated_at, key)`: `draft -> ready_for_issue` after re-validation (stale timestamps refused).
4. **Issue** -- `issue_prepared_carrier_invoice(id, expected_updated_at, reason, key)` (owner/admin): wraps the existing atomic `issue_carrier_invoice` (0144/0145, unchanged), then, in the same sub-transaction, freezes the **issuance terms** (factored: relationship, factor, NOA, routing, advance/fee/reserve with a SHA-256 fingerprint; direct: the direct-billing status only, no factoring instructions) and links the dispatch-fee receivable. A configuration race rolls the whole step back (`STALE_CONFIGURATION`).
5. **Reissue** -- `preview_carrier_invoice_reissue(id)` / `reissue_carrier_invoice(id, expected_updated_at, reason, key)` (owner/admin): only for an issued, unpaid invoice with NO factoring submission (even a withdrawn one), unchanged total. In one sub-transaction: the original is **voided** (immutable reason `Reissued: ...`, never deleted), its ledger rows are released, a replacement draft is created for the same loads, marked ready and issued with the CURRENT server-resolved terms/routing, the terms record, the immutable reissue link and the audit row are written. Any failure rolls everything back, so there is never a voided original without its replacement.
6. **Discard** -- `discard_carrier_invoice_draft(...)`: a never-issued draft cannot be voided (the schema requires an invoice number on a voided invoice), so it is *discarded*: its loads are released and it can never be readied or issued; the record is kept.
7. **Factoring** -- the factoring panel is offered only to owner/admin for a correctly ISSUED freight invoice; drift / direct-billing / uncontrolled issuance shows a "reissue required" callout and NO submit control.

## Treatment of dispatch fees
The dispatch-service fee is a separate carrier-to-dispatcher receivable and never part of a freight invoice, its total, its recipient or the factored amount: (a) freight invoices carry only `freight_charge` lines (a `dispatch_service_fee` line makes an invoice unfactorable, `DISPATCH_FEE_ON_INVOICE`); (b) the preview shows the estimated fee from the carrier's approved, effective 0145 agreement under a separate heading; (c) at issuance a separate `dispatch_service_invoice` DRAFT for the same carrier and loads is created and linked (immutable `carrier_invoice_dispatch_fee_links_0157`); when no agreement is effective nothing is created and the reason is shown; (d) a reissue carries the existing link over (no second fee receivable). **Issuing the dispatch-service invoice stays a separate step of the existing 0145 path** (percentage fees need the freight invoice issued first); this proposal does not issue it.

## Existing boundary and remaining approvals
The unchanged signed-off 0144 `issue_carrier_invoice` admits owner/admin/accountant.
